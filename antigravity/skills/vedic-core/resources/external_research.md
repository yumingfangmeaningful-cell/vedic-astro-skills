# 外部检索协议：OmniSeek + Web Search 双开

> **适用范围**：全部 6 个 vedic skill（reader / calculator / core / career / love / rectifier）。
>
> **一句话规则**：需要"当前可验证事实"，或需要"开放网够不到的深度"时，
> **默认 OmniSeek + web search 双开，不凭训练记忆作答。**

---

## 0. 为什么要有这条规则

训练记忆有三种失效方式，而且都是**静默**发生的（模型不会提示你它记错了）：

1. **过期** —— 政策、行业、考试/签证规则、库版本随时间变，记忆停在某个时点。
2. **编造** —— 记不清的具体值（历史时区偏移、经纬度小数、经典原文出处）会被"补全"成看起来合理的数字。
3. **单一口径** —— 公开网页常常互抄同一条口径；第一手经验在登录墙内、评论区里、音视频中，普通搜索够不到。

星盘工作对第 1、2 类错误**零容忍**：

> **出生地时区/夏令时错 1 小时 → Lagna 可能整体错一个星座 → P1-P12 全盘结论作废。**

这类错误不会报错，只会安静地把整份报告变成"精确的错误"。

## 1. 必须双开的场景（MUST）

| 场景 | 典型问句 | 主要涉及 |
|:---|:---|:---|
| 历史时区 / 夏令时 | "该地该年是否执行夏令时？出生当天钟面相对 UTC 的实际偏移是多少？" | calculator / reader / rectifier |
| 坐标与行政区变更 | "这个县在当年属于哪个市？取哪个点的经纬度？" | calculator |
| 现实世界当前事实 | 行业景气、岗位门槛、证书/考试、政策与时间线、公司现状 | career / core(QA) / love(QA) |
| 公共事件日期核对 | "某项政策/某次地震/某公司上市的准确日期" | rectifier |
| 依赖与 API 现状 | PyJHora / pyswisseph / dashaflow 的当前版本、已知 bug、Python 支持范围 | calculator |
| 经典文献引证 | BPHS / Jaimini Sutras 原文与出处、KN Rao 著作原话 | core / career / love |

**判据（满足任一即双开）：**

- 答案会随时间变化；
- 答案是一个**具体值**（日期、偏移、坐标、版本号、条款/页码），错了会传导进计算或结论；
- 你发现自己正在写"据我所知""一般来说""通常是""印象中"。

## 2. 双开怎么执行

1. **拆问题**：先把需求拆成可独立核实的事实问句，一次一问。不要把整段用户需求原样丢给搜索。
2. **同时发**：同一个事实问句**同时**交给 `omniseek_search` 和 web search。两边结果都要看，不是谁先返回用谁。
3. **按需深挖**（OmniSeek 侧）：
   - `omniseek_read` —— 网页 / PDF / arXiv 正文
   - `omniseek_view` —— 图片、图表、视频帧
   - `omniseek_transcribe` —— 音视频本地转写
   - `omniseek_paper_enrich` / `omniseek_field_skeleton` —— 文献与引用网络
   - `omniseek_gather` —— 多工具并行，一次返回
   - `omniseek_sources` —— 不知道该问谁时，先看能覆盖哪些源
4. **交叉比对**：
   - 两边一致 → 采用，记下**来源 + 访问日期**。
   - 两边冲突 → 以一手/官方源为准（官方文档、标准机构、原始论文 > 媒体报道 > 二手博客/论坛），并在正文写明存在分歧。
   - 都查不到 → 写"未能核实"，**禁止用记忆补缺**。
5. **落到动作**：时区/坐标类的核实结论必须能落到一个具体操作（用哪个 `tz_str`、是否需要手工修正偏移、取哪个坐标点），并写进 structured_data 的备注。

## 3. 禁止事项（MUST NOT）

1. **禁止用检索结果覆盖计算结果**
   行星位置 / Dasha / SAV / Shadbala / 分盘，一律以 vedic-calculator engine 为准（见各 skill 的「数据源优先级铁规」）。
   外部检索只负责**输入**（时区、坐标、事件日期）和**现实世界事实**，不负责盘面数据。

2. **禁止混入其他流派**
   解读体系锁定 KN Rao / Parashari。网上搜到的其他体系口径不得进入推导链。

3. **禁止检索用户隐私**
   不得把用户姓名、完整出生信息组合（日期+时间+地点）、联系方式、`user_context.md` 的任何内容作为查询词发出去。
   核实事件时只检索**去标识化的公共事实**：
   - ✅ "2015 年 3 月某地是否有某项政策"
   - ❌ "张三 2015 年 3 月结婚"

4. **盲审阶段不检索用户本人**（vedic-core Step 1-3）
   该阶段只有盘面数据，检索用户其人违反逻辑隔离原则。

5. **禁止把外部事实当成盘面证据反推**
   外部事实只能用于校准输入、补充现实背景，不能用来倒推"你的盘说的就是这件事"（见各 skill 的反确认偏误规则）。

---

## 4. 结果怎么写进报告

- 外部事实与盘面推导**分开写**，外部事实统一标注：`[外部核实 · 来源 · YYYY-MM-DD]`
- 双开结果有分歧的，把分歧写出来，不要挑一个装作确定
- 只有 web search 可用时，标注：`[单通道核实 · 置信度降级]`
- 完全没核实的，标注：`[未核实]`，并说明需要用户自行确认什么

## 5. 降级路径

| 状态 | 做法 |
|:---|:---|
| OmniSeek + web 均可用 | **默认双开** |
| OmniSeek 未安装 / 未启动 / 鉴权失败 | 只走 web search，结论标注"单通道核实"；并把安装方式（README「外部检索」一节）告诉用户 |
| 完全无联网 | 明确告诉用户"这条我无法核实"，列出需要用户自行确认的清单（尤其时区/夏令时），**禁止编造** |

## 6. 安装（一次性）

OmniSeek 是自托管的 MCP 服务，跑在用户自己机器上，无云端、无遥测。

```bash
git clone https://github.com/Battam1111/omniseek.git && cd omniseek
docker compose up -d
docker compose logs omniseek        # 首次启动打印 bearer token
curl -s http://127.0.0.1:8765/healthz   # {"ok":true}
```

接入 Claude Code：

```bash
claude mcp add --transport http omniseek http://127.0.0.1:8765/mcp \
  --header "Authorization: Bearer <token>"
```

其他客户端：把 MCP 端点指向 `http://127.0.0.1:8765/mcp`，带 `Authorization: Bearer <token>`。
token 存于 `~/.omniseek/credentials/omniseek_http.json`。

项目地址与完整文档：https://github.com/Battam1111/omniseek
